# data/

Inputs to MMF. Everything here is documentation: manuscripts, abstracts, codebooks and user guides. There is no row-level or patient data in this folder, and MMF never reads any. All files are tracked in git.

`manifest.json` records the sha256 of every file, so a run can be traced to the exact documents. Regenerate it with:

```bash
uv run mmf manifest $(find data -type f ! -name README.md ! -name manifest.json ! -name .DS_Store | sort)
```

Which files a run uses, and the role of each source, is set in `configs/suid.yaml`.

### manuscripts/literature/

Generated by `scripts/fetch_pubmed.py` from PubMed (NCBI E-utilities, retrieved 2026-10-26). Regenerate rather than edit:

```bash
uv run python scripts/fetch_pubmed.py --out data/manuscripts/literature
```

| File | What it is |
|---|---|
| `suid_literature_abstracts.md` | Abstracts of SUID and respiratory-development papers by the Ramirez lab and the Lavista Ferres group. Pipeline input. Claims from it are abstract-level. |
| `suid_literature_pmids.json` | PMIDs included in the abstracts file. |
| `ramirez_lavista_bibliography.md` | The full publication record from the same queries (250 records). Reference only, not a pipeline input. |
| `records.json` | Raw records as fetched (title, abstract, ids, MeSH). |
